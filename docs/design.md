**バージョン**: 1.4  
**作成日**: 2026-06-10  
**更新日**: 2026-10-02（カメラOCR・音声入力・外部API連携を削除）  
**対象リポジトリ**: https://github.com/pcmnb/parking

---

## 1. システム概要

来訪者の車両を管理するWebアプリケーション。受付担当者がスマートフォン・タブレット・PCで操作し、訪問者の入庫・出庫を記録する。

### 主要な設計方針

- **シングルページアプリ**: `index.html` 1ファイルで完結（ビルド不要、依存ライブラリなし）
- **オフライン動作**: データはブラウザのlocalStorageに保存。ネット不通でも入出庫登録・閲覧が可能
- **ゼロバックエンド原則**: 外部APIは使用せず、すべての処理をクライアントで完結
- **ユニバーサルデザイン**: 高齢者・色弱者を考慮した配色・文字サイズ・操作設計

## 3. コンポーネント設計

### 3.1 フロントエンド（index.html）

単一ファイル構成。外部CSS・JSライブラリは一切使用しない。

| 責務 | 実装箇所 |
|---|---|
| ルーティング（タブ切替） | `showView(v)` 関数 |
| 入庫登録 | `register()` 関数 |
| 出庫処理 | `checkout(id, e)` 関数 |
| 一覧表示・複合フィルター | `renderList()` 関数 |
| ナンバー入力時の自動入力 | `autofillFromPlate()` 関数 |
| ステータスフィルター切替 | `setStatusFilter(mode)` 関数 |
| 日付検索入力処理 | `onDateSearchInput()` 関数 |
| 日付文字列の正規化 | `normalizeDate(s)` 関数 |
| 編集モーダル | `openEdit(id)` / `saveEdit()` 関数 |
| CSV出力 | `doDownloadCSV(mode)` 関数 |
| CSV読み込み | `doImportCSV()` 関数 |
| データ永続化 | `loadRecords()` / `saveRecords()` 関数 |

**タッチ操作の考慮**  
スマートフォンでのスクロール中に誤ってカードをタップしないよう、`touchstart` / `touchend` のY座標差分（10px超で無効化）を判定してから `openEdit()` を呼び出す。

## 4. データ設計

### 4.1 localStorageスキーマ

**キー**: `parking_records`  
**値**: JSON配列

```json
[
  {
    "id": 1749480000000,
    "date": "2026-06-10",
    "inTime": "09:30",
    "outTime": "11:45",
    "name": "山田太郎",
    "dest": "営業部 鈴木",
    "plate": "1234"
  }
]
```

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | number | `Date.now()` で生成するユニークID |
| `date` | string | `YYYY-MM-DD` 形式（ローカル日付） |
| `inTime` | string | `HH:MM` 形式（24時間） |
| `outTime` | string \| null | `HH:MM` または `null`（未出庫） |
| `name` | string | 訪問者名・会社名（省略時は「不明」） |
| `dest` | string | 訪問先・担当部署（省略時は「不明」） |
| `plate` | string | ナンバープレートの数字部分（1〜4桁） |

### 4.2 CSVフォーマット

文字コード: UTF-8 BOM付き（Excel互換）  
1行目: ヘッダー行

```
日付,入庫時刻,出庫時刻,訪問者名,訪問先,ナンバー
2026-06-10,09:30,11:45,"山田太郎","営業部 鈴木",1234
2026-06-10,10:00,,"〇〇株式会社","総務部",5678
```

| 列 | フィールド | 備考 |
|---|---|---|
| 日付 | date | `YYYY-MM-DD` |
| 入庫時刻 | inTime | `HH:MM` |
| 出庫時刻 | outTime | 空文字 = 未出庫 |
| 訪問者名 | name | ダブルクォートで囲む |
| 訪問先 | dest | ダブルクォートで囲む |
| ナンバー | plate | 数字のみ |

## 5. 検索・フィルター設計

### 5.1 複合フィルターの概念

一覧・出庫タブでは、以下3つのフィルターを組み合わせて絞り込みができる。

| フィルター | 種別 | 初期値 |
|---|---|---|
| ナンバー検索 | テキスト入力（数字） | 空欄 |
| 日付検索 | テキスト入力（日付） | 当日 |
| ステータスフィルター | ボタン選択 | すべて |

### 5.2 表示モードの判定ロジック

```
isDefaultView = (日付=当日) AND (ステータス=すべて) AND (ナンバー未入力)
```

| 条件 | 表示モード | ヘッダー | 件数ラベル |
|---|---|---|---|
| isDefaultView = true | 通常表示 | 今日の日付（日本語形式） | 非表示 |
| それ以外 | 絞り込み表示 | 🔍 フィルター内容 | 「N件が見つかりました」 |
| 日付欄が空 | 通常表示（全日付） | 今日の日付（日本語形式） | 非表示 |

### 5.3 日付検索の正規化（normalizeDate）

入力受付フォーマットと内部フォーマットの変換。

| 入力形式 | 例 | 変換後（内部形式） |
|---|---|---|
| YYYYMMDD（8桁） | `20260601` | `2026-06-01` |
| YYYY/MM/DD | `2026/06/01` | `2026-06-01` |
| YYYY-MM-DD | `2026-06-17` | `2026-06-17`（そのまま） |

8桁の数字が揃った時点で `YYYY/MM/DD` 形式に自動整形して表示する。年は必ず4桁に制限。

### 5.4 ナンバー検索ロジック

| 入力 | 動作 |
|---|---|
| `0000` | 全期間の全データを表示（日付フィルター無効化） |
| 先頭が `0` の入力（`01` 等） | 先頭0を除去した値で完全一致検索 |
| その他の数字 | 部分一致検索 |
| 空欄 | ナンバーフィルターなし |

### 5.5 ステータスフィルター

| モード | 表示対象 | ボタン色 |
|---|---|---|
| すべて（初期値） | 入庫中・出庫済みの両方 | 紺色（アクティブ） |
| 入庫中 | `outTime === null` のレコードのみ | 紺色（アクティブ） |
| 出庫済み | `outTime !== null` のレコードのみ | 紺色（アクティブ） |
| 非選択 | — | グレー |

### 5.6 自動入力ロジック（autofillFromPlate）

入庫タブでナンバー入力後1000ms後に実行（デバウンス）。

```
1. plate-number の値を取得
2. /^\d{1,4}$/ に一致しなければ処理終了
3. 同一ナンバーで outTime=null のレコードが存在する場合（入庫中）:
   a. そのレコードの name・dest を取得
   b. トースト「⚠️ このナンバーはすでに入庫中です」を表示
   c. 新規レコードとして自動登録しフォームをクリア
   d. 成功メッセージ「✅ 過去データから自動入庫しました（name）」を3秒表示
   e. 処理終了
4. records から plate が一致するレコードを全件取得
5. 一致なし → 処理終了
6. 日付+入庫時刻の降順でソートし最新レコードを取得
7. 最新レコードの name・dest で自動登録しフォームをクリア
8. 成功メッセージ「✅ 過去データから自動入庫しました（name）」を3秒表示
```

## 6. セキュリティ設計

| 脅威 | 対策 | 状態 |
|---|---|---|
| XSS | `esc()` 関数で `r.name` / `r.dest` をHTMLエスケープして innerHTML に埋め込む | 対応済み |
| データ漏洩 | データはlocalStorageのみ。サーバーへのデータ送信なし | 対応済み |

### 6.1 XSS対策の実装（2026-06-10 追加）

`index.html` の `renderList()` 関数内で、ユーザー入力値を innerHTML に埋め込む際に `esc()` 関数を適用する。

```javascript
function esc(s){
  return String(s)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}
```

**エスケープ対象**: `r.name`（訪問者名）、`r.dest`（訪問先） — 計4箇所  
**エスケープ不要**: `r.plate`（数字バリデーション済み）、`r.date` / `r.inTime` / `r.outTime`（システム生成）

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| デバイス | スマートフォン・タブレット・PC |
| ブラウザ | モダンブラウザ（Chrome, Safari, Edge） |
| オフライン | 全機能が利用可能 |
| レスポンシブ | max-width: 600px でセンタリング |
| 最小文字サイズ | 20px（フィールドラベルは22px） |
| ボタン最小高さ | 48px以上（タップ操作対応） |
| 色覚対応 | 赤緑を識別色に使用しない（青・オレンジ・グレー体系） |
| データ容量 | localStorageの上限（通常5MB）に依存 |
